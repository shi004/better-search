# 信源核验与处理（Source Handling）

> 本文件只回答“拿到信源后怎么核验、裁决、标注”。
> 信源清单、分级与账号主体判定见 `sources.md`；输出格式见 `report-template.md`；检索与抓取见 `../SKILL.md`。
> 本文件与 `sources.md` 共同承载原信源规则；旧文件已删除，不保留兼容路径。

## 1. 独立来源与交叉验证（交叉引用）

1. 先明确要验证的具体断言。
2. 找 **2 个以上互不引用**的独立来源（避免循环引用）。
3. 验证独立性 = 不同作者、不同发布方、不同组织。
4. 比对实质内容是否一致（措辞差异可接受）。
5. 每条发现标注：已核实 / 部分核实 / 未核实。
6. **循环引用判定**：B 引用 A 只算 1 个来源；多个来源引用同一原始研究时，引用原始研究。
7. 优先一手来源；二手只在无一手或一手不可得时使用，并标注。
8. 关键结论/不稳定信息（价格、政策、版本、数字）必须额外交叉核对，争议大时增加来源数量。
9. **仅线索不计入独立来源数**；只有找到原始出处、官方确认或独立一手证据后，才可按实际性质计入。
10. **同一原文在多个平台/账号的转载、截图、二次剪辑只算 1 个来源**；必须追溯原始出处，不能把多平台搬运当成多源交叉。
11. 同一平台多个账号转同一稿、同一视频的切片/搬运，不算独立来源。

### 1.1 线索处理与核验链

1. **发现**：记录平台/账号/URL/日期/待核验断言；搜索摘要、封面、截图只用于发现。
2. **回溯**：找原始出处（官网、原帖、原视频、原文），判断账号主体与原创/转载；微信公众号按 `sources.md` §2.1 判定。
3. **核验**：官方确认、独立来源交叉，或按第 6 节评估经验证据；不能只靠同一平台的重复内容。
4. **处理**：标为 `已核验` / `部分核验` / `仅线索`；写明采纳、降级、排除或进入知识空白。
5. 不能核验的线索可以保留在报告中，但不得作为关键结论证据，也不得计入置信度来源数。

## 2. 冲突处理

- **记录全部冲突来源**及各自证据（不要只留下支持自己结论的一方）。
- 评估每个来源的可信度（`sources.md` 第 3 节 Tier + 本文件第 3 节偏见 + 第 4 节时效）。
- 呈现双方证据与权威判断，明确标注不确定性。
- **裁决顺序**：版本匹配的官方一手来源 > 官方发布说明/变更日志 > 一手示例或数据 > 可靠二手 > 其他二手；裁决理由写进输出。
- **未核验线索不进入冲突裁决**；先核验、找原始出处，再比较。
- 经验类冲突（社区经验之间的分歧）另见第 6.5 节。

## 3. 偏见检测清单

引用前逐条检查；命中即在来源分析中标注并降低置信度：

1. **商业利益**：是否在推销相关产品/服务？
2. **赞助/资助**：是否带赞助或资金关系？
3. **利益冲突**：作者是否从结论中获益？
4. **地理/文化偏见**：是否只覆盖单一地区/文化？
5. **时间偏见**：来源日期是否集中在某一时期？
6. **挑樱桃（cherry-picking）**：是否承认相反证据？
7. **逻辑谬误**：把相关当因果、以权威代替证据等。
8. **免责声明/局限**：是否披露数据来源、样本与限制？

## 4. 时效规则

| 类别 | 最长期限 | 原因 |
|---|---|---|
| 安全漏洞 | 6 个月 | 威胁演变快 |
| 框架版本 | 1 年 | API/实践变化 |
| 云服务文档 | 1 年 | 频繁更新/下线 |
| API 参考 | 1 年 | 破坏性变更常见 |
| 架构模式 | 长期有效 | 核心模式稳定 |
| 方法论参考 | 长期有效 | 基础著作稳定 |
| 语言规范 | 按版本长期有效 | 每版本永久 |
| 研究论文 | 3 年 | 需查后续工作 |
| 行业趋势报告 | 1 年 | 只引用当版 |

过期处理：

1. 检查是否有新版本。
2. 稳定概念可引用并标注 `[Published {year}; concept remains current]`。
3. 时效性内容找当前来源，或把“信息过时”写入知识空白。
4. 不得把过期的安全通告当作当前威胁情报。

## 5. 证据标准与引用格式

**证据标准**：直接引用或具体数据；完整归属与引用；技术文档带版本信息；带发布日期或最后更新日期；作者资质（可得时）。

**引用格式**：

```
[1] {Author/Organization}. "{Title}". {Publication/Website}. {Date}. {Full URL}. Accessed {YYYY-MM-DD}.
```

**每个来源的必需元数据**：`来源 URL | 域名 | 访问日期 | 信誉分（Tier） | 验证状态`

**平台来源的额外元数据**：`平台/账号 | 账号主体/认证 | 内容性质（原创/转载） | 发布日期 | URL | 访问日期 | 核验状态`

**付费墙/受限来源**：标 `[Paywalled]`/`[Restricted Access]`，给出 URL，寻找开放获取替代；找不到时记入“知识空白”。

**禁止**：编造 URL、标题、作者、数字、日期；引用不到就不写该结论；截图、短视频封面、搜索摘要不能替代原文。

## 6. 经验类证据规则（社区经验为主要依据的场景）

### 6.1 适用场景

当官方/权威来源对“具体怎么做/实际体验如何”基本不覆盖，或只给规则而实操细节只能来自实践者时，适用本节。典型场景：

- 游戏攻略（打法/路线/配装，随版本变化）；
- 菜谱与烹饪；
- 软件/设备使用技巧、DIY/维修；
- 旅行路线与经验、消费体验/评测（主观）；
- 学习资源与方法、求职/留学经验；
- 办事中的实操细节（非官方规定部分）；
- 平台社区口碑/真实体验（论坛、贴吧、小红书、B 站、知乎、微博、小黑盒、Steam 评测、微信公众号、抖音、快手、YouTube、个人博客等）。

这些场景里若包含规则/事实（政策、收费、时限、安全、版本变更、官方参数），那部分**仍按 `sources.md` 第 1-3 节和本文件第 1-5 节处理**；平台清单与账号主体判定见 `sources.md` §1.8/§2.1。

### 6.2 任务分层（先判类型）

- **规则/事实型**：按 `sources.md` 第 1-3 节（官方/一手优先、Tier）与 `source-handling.md` 第 1-5 节（交叉验证、时效、冲突）处理。
- **经验/操作型**：以社区/实践者为主要依据，按 6.3 经验证据标准。
- **混合型**：分开取证、分别标注；官方事实回退 Tier 规则，经验细节按 6.3；输出中标明每条结论的性质。

### 6.3 经验证据标准（替代机械 Tier 排除）

对 `sources.md` §1.8 所列平台（论坛、贴吧、小红书、B 站、知乎、微博、小黑盒、Steam 评测、微信公众号、抖音、快手、YouTube、美食博客、个人博客等），按下述标准评估（不因“不是官方”直接判 0；仍须标注来源性质）：

1. **可复现**：步骤/条件完整，普通人能照做；只给结论不给过程的不算强证据。
2. **共识度**：≥2–3 个独立实践者一致（争议大取更多）；单一来源标“个例”，不得当普遍结论。
3. **版本/时间匹配**：游戏版本号、软件版本、设备型号、地区/政策时间；过期内容降级或注明。
4. **作者利益披露**：商家/带货/推广/赞助须标注并降权，但不直接排除。
5. **样本范围**：单次体验 vs 大量用户反馈；区分“个例/常见”。
6. **可验证出处**：能给出链接、日期、版本；给不出且无法复现的不作为证据。
7. **安全/合规**：不得用于规避安全机制或违法用途。
8. **账号主体与原创性**：账号是否可识别、内容是否原创；转载、切片、搬运按二手/线索，不按一手经验。

### 6.4 呈现要求

- 每条经验结论标注：来源性质（官方/经验/个例/共识）+ 日期或版本 + 核验状态。
- 输出中区分“官方事实”“实践者经验”“我的推断”三类。
- 每条线索记录：平台/账号 → 核验结果 → 处理（采纳/降级/未核验/知识空白）。
- L1 可只给 1–2 条实践来源（带日期/版本）；L2 用证据表的“性质/核验状态”列；L3 在“发现”中标注证据性质/版本，并在线索表中保留未核验项。

### 6.5 冲突处理（经验类）

- 裁决顺序：版本匹配 > 共识度 > 可复现性 > 作者利益披露。
- 无法裁决时给多个方案 + 各自适用条件，不强行统一；明确哪些是社区经验、哪些有官方依据。
- 未核验线索不参与裁决。

### 6.6 高风险例外（不得只靠社区经验）

医疗/用药/心理健康、金融投资、法律、危险 DIY/维修、未成年人安全、安全机制规避等：必须官方/专业来源优先；社区经验只能作补充并给风险提示；沿用第 3 节偏见与第 4 节时效规则。

### 6.7 与 Tier 的关系

- 经验任务不机械套用 `sources.md` §1.7 的 lead-only 限制；来源按 6.3 评估，仍需标注性质。
- 一旦结论涉及官方可查事实，回退 `sources.md` 第 3 节 Tier 与 `sources.md`/本文件相关规则。
- 本节的放宽范围仅限“经验/操作型”证据，不放宽安全、法律、医疗、金融等高风险领域。

## 7. 处理边界

- 本文件**不写**：如何检索/抓取（`../SKILL.md`）、如何操作浏览器（`use-my-browser`）、输出文档结构（`report-template.md`）、信源清单与账号主体判定（`sources.md`）。
- 冲突在输出中的呈现格式见 `report-template.md`；置信度定义与阈值见 `report-template.md` 第 3 节。
